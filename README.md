# Семейный бюджет

Android-приложение, которое помогает семье систематизировать финансы. Пользователь отвечает на простые вопросы
(онбординг), приложение собирает «финансовую картину» — ключевые показатели с диаграммами, — после чего учёт ведётся
вручную, а для каждого показателя есть подсказка: что это, как считается, какая норма и как улучшить.

Всё работает **локально и офлайн**: нет бэкенда, регистрации, сторонней аналитики и разрешения `INTERNET`.

> **Статус.** Бизнес-логика (`:domain`) собрана и покрыта 104 unit-тестами. Android-часть (`:app`) написана целиком;
> в среде разработки не было Android SDK, поэтому **Gradle-сборка `:app` ещё не запускалась**. Исходники проверены
> ktlint/detekt и скомпилированы Kotlin'ом против Compose Multiplatform с заглушками Android-библиотек (0 ошибок) —
> подробности и список непроверенного в разделе 10 [DECISIONS.md](DECISIONS.md), порядок действий — в
> [«Первая сборка»](#первая-сборка).

## Возможности

- **Онбординг:** 10 вопросов по одному на экран, прогресс-бар, возврат назад, пропуск необязательного, пояснение
  «зачем мы это спрашиваем», валидация и разделители тысяч. Ответы можно редактировать в любой момент.
- **Сводка:** свободный денежный поток, норма сбережений, долговая нагрузка, подушка в месяцах, доля обязательных
  расходов, чистый капитал. Режимы **План / Факт**, статус = цвет + значок + слово, подсказка «?» у каждой карточки.
  Диаграммы: структура расходов (кольцо), доходы и расходы по месяцам (столбцы), прогресс целей.
- **Операции:** быстрая форма (сумма → категория → «Сохранить»), группировка по дням, фильтры и поиск, свайп-удаление
  с отменой, обзор месяца с планом из опроса, лимиты по категориям, регулярные ежемесячные операции с подтверждением.
- **Цели:** прогресс, ручное пополнение, прогноз срока и сумма «сколько откладывать в месяц».
- **Напоминания:** вечерние или еженедельные, мягкие, не приходят, если операции уже вносились; переживают перезагрузку.
- **Данные:** экспорт/импорт JSON (замена или слияние), выгрузка операций в CSV, удаление всех данных.
- **Безопасность:** необязательная блокировка биометрией/PIN устройства; `allowBackup=false`.
- Светлая и тёмная темы, Dynamic Color (Android 12+), русский интерфейс (все строки — в `strings.xml`).

## Стек

Kotlin · Jetpack Compose (Material 3) · MVVM + Clean-lite · Room · Hilt · Coroutines/Flow · DataStore ·
Navigation Compose · WorkManager · kotlinx.serialization. Графики нарисованы на Compose Canvas — обоснование и
таблица версий в [DECISIONS.md](DECISIONS.md#1-библиотека-графиков-и-версии-зависимостей-подтверждение-перед-этапом-1).

## Структура

```
domain/   чистый Kotlin/JVM: модели, расчёт показателей, валидация опроса, прогноз целей,
          расписание регулярных операций, бэкап (кодек, проверка, слияние), CSV
app/      Android: Room (data/db), репозитории (data/repo), уведомления, блокировка,
          Compose-экраны (ui/…), навигация, Hilt (di)
config/   конфигурация detekt;  .editorconfig — ktlint
```

Пороги «нормы» лежат в одном файле — `domain/src/main/kotlin/app/fingramm/domain/metrics/Benchmarks.kt`.

## Сборка

Нужны JDK 17 и Android SDK (платформа 36). Проще всего открыть проект в Android Studio.

```bash
./gradlew assembleDebug          # отладочная сборка
./gradlew installDebug           # установка на подключённое устройство/эмулятор
./gradlew assembleRelease        # release (без подписи, если нет keystore.properties)
```

Подпись release: положите рядом с `build.gradle.kts` файл `keystore.properties` (в `.gitignore`):

```properties
storeFile=release.jks
storePassword=…
keyAlias=…
keyPassword=…
```

### Первая сборка

Android-часть не собиралась в среде, где она писалась (см. статус выше). Рекомендуемый порядок:

1. `./gradlew :domain:test` — должно пройти без Android SDK (104 теста).
2. `./gradlew assembleDebug` — возможны мелкие ошибки на стыке с реальными Room/Hilt/WorkManager (KSP, манифест, ресурсы).
3. `./gradlew test` — unit-тесты `:app` (репозитории на Room in-memory через Robolectric, расчёт времени напоминаний).
4. **Закоммитьте `app/schemas/`** — Room создаёт там JSON-схему при первой сборке; она нужна тесту миграций.
5. `./gradlew connectedDebugAndroidTest` — UI-тесты онбординга и проверка схемы (нужен эмулятор).
6. `./gradlew lintRelease assembleRelease` — Android Lint уровня error должен пройти.

## Проверки качества

```bash
./gradlew ktlintCheck detekt     # стиль и статический анализ (ktlintFormat — автоисправление)
./gradlew test                   # unit-тесты
./gradlew lintRelease            # Android Lint
```

То же выполняет CI (`.github/workflows/ci.yml`): быстрый job для `:domain` без Android SDK, полный job для `:app`
и ручной job с эмулятором для инструментальных тестов.

Тесты:

| Что | Где | Как запускается |
|---|---|---|
| Показатели, граничные случаи (ноль дохода, долги > дохода, пороги), деньги, валидация, прогноз, расписание, бэкап | `domain/src/test` | JVM |
| Репозитории: фильтры, поиск, регулярные операции, экспорт → очистка → импорт | `app/src/test` | Robolectric |
| Время напоминаний | `app/src/test` | JVM |
| UI онбординга, миграции Room | `app/src/androidTest` | эмулятор/устройство |

## Формат резервной копии

```jsonc
{
  "app": "fingramm",
  "schemaVersion": 1,
  "exportedAt": "2026-10-10T10:00:00Z",
  "data": {
    "profile": {…}, "survey": {…}, "incomeSources": […], "assets": […], "debts": […],
    "categories": […], "transactions": […], "recurringTemplates": […], "goals": […],
    "categoryLimits": […], "reminder": {…}
  }
}
```

Суммы — целые числа в копейках/центах, даты — `yyyy-MM-dd`. Файл не шифруется. При несовместимых изменениях формата
увеличивайте `BACKUP_SCHEMA_VERSION` в `domain/…/backup/BackupData.kt`.

## Миграции базы данных

`AppDatabase.VERSION` сейчас 1. Для новой версии: увеличьте `VERSION`, добавьте `Migration` в `AppDatabase.MIGRATIONS`,
закоммитьте новый файл схемы из `app/schemas/` — `MigrationTest` проверит путь с каждой старой версии.
