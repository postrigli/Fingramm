# Принятые решения

Здесь зафиксированы выборы там, где ТЗ допускало несколько вариантов или было неоднозначным.
Принцип: если есть сомнение — берём простое решение и записываем его сюда.

## 1. Библиотека графиков и версии зависимостей (подтверждение перед этапом 1)

**Графики — собственные на Compose Canvas, без Vico и MPAndroidChart.**

| Причина | Подробности |
|---|---|
| Нужны кольцевая, столбчатая и линейные диаграммы | В Vico (cartesian) нет кольцевой диаграммы — её всё равно пришлось бы рисовать самим. |
| MPAndroidChart | View-based, нужен JitPack, давно не развивается, плохо дружит с темой Material 3 и TalkBack. |
| Доступность | Свой код даёт полный контроль: легенда с суммами и процентами рядом с диаграммой, `contentDescription` с данными, не только цвет. |
| Размер и поддержка | Ноль зависимостей, ~200 строк (`ui/charts/Charts.kt`). Минус — нет анимаций и подсказок по касанию; для v1 они не нужны. |

вырасти). Обновляйте пакетом (AGP + Kotlin + KSP + Hilt + Compose BOM) и сверяйте совместимость.

## 2. Архитектура

- **Два Gradle-модуля.** `:domain` — чистый Kotlin/JVM (модели, расчёты, валидация опроса, прогноз целей,
  расписание регулярных операций, формат бэкапа, слияние, CSV). `:app` — Android (Room, Hilt, Compose).
  Так вся бизнес-логика тестируется без эмулятора, а «без бизнес-логики в Composable» обеспечено структурой.
- «Clean-lite»: репозитории — конкретные классы в `data/repo`, интерфейсов-абстракций над ними нет; use-case'ы
  заменены чистыми функциями домена.
- Единая функция переходов мастера опроса (`SurveyWizard`) используется экраном, ViewModel и тестами.
- Черновик онбординга живёт в `ViewModel` и **не переживает убийство процесса** (при возврате опрос начнётся заново).

## 3. Деньги и показатели

- Суммы — `Long` в копейках/центах; `Double` только для долей. Доли считаются через `BigDecimal` с HALF_UP,
  сравнение с порогами — точное (`BigInteger`), «сколько месяцев/взносов» округляется вверх.
- **Подушка — часть сбережений.** Ликвидные сбережения = `max(сумма по местам хранения, подушка)`, чтобы не считать дважды.
- **Пороги** (`domain/metrics/Benchmarks.kt`, единственное место): свободный поток/норма сбережений — ориентир 10–20%,
  «внимание» при < 10%, «риск» при отрицательном; долговая нагрузка — норма ≤ 30%, «риск» > 40% (30–40% — «внимание»;
  ТЗ говорит «30–35%», берём нижнюю границу); подушка — «риск» < 1 мес., «внимание» < 3 мес.;
  обязательные расходы — норма ≤ 50%, «риск» > 70% (70% — наше решение, ТЗ задаёт только 50%).
  Числа из `Benchmarks` подставляются в тексты подсказок, а не зашиты в строки.
- **Нулевой доход:** доли (норма сбережений, доля обязательных) не определены (показывается «—») и получают статус
  «риск», если расходы есть. Без платежей по долгам долговая нагрузка — 0% и «в норме», даже при нулевом доходе.
- **Нет расходов:** подушка в месяцах не определена («нет оценки»).
- Чистый капитал: статус «внимание» только если он отрицательный; «динамика важнее значения» реализована режимом
  «Факт»: капитал = исходный + накопленный результат операций (доходы − расходы) по выбранный месяц включительно.
- **Режим «Факт»:** подушка в месяцах считается от суммы подушки из опроса (операции её не меняют) и расходов выбранного месяца.
  Платежи по долгам в факте — операции в категориях с флагом «платежи по кредитам» (предустановленная «Кредиты»).
- **Переменные расходы «не знаю»:** в плане 0 с пояснением; после первого полного календарного месяца после создания
  профиля берётся среднее по последним (до трёх) полным месяцам с операциями. Месяц создания профиля неполный и не учитывается.
- Остаток долга не указан → в капитале 0 и предупреждение на дашборде.

## 4. Опрос

- **Валюта выбирается на приветственном экране**, а не в конце: суммы на всех экранах нужно подписывать символом.
  Менять валюту можно в «Ещё → Ответы опроса» (суммы не пересчитываются — мультивалютность вне v1).
- Кредиты — одна агрегированная запись «Кредиты и долги» (платёж + необязательный остаток), как в вопросе ТЗ.
  Модель (`Debt`) допускает список.
- Источники дохода и активы — списки «название + сумма»; пустое название заменяется «Доход»/«Актив».
- Расходы «по категориям» — редактируемые строки, предзаполненные типовыми названиями; учитывается сумма строк.
- **Цели:** опрос создаёт цели один раз при онбординге; дальше они редактируются только на вкладке «Цели».
  Если главная цель — подушка, уже накопленная подушка засчитывается как прогресс по ней.
- «Раз в месяц» как частота учёта → недельное напоминание по умолчанию (режимов реже недели нет).
- Пропуск необязательного шага сбрасывает введённое на нём (нет неполных данных).
- Валидация: размер семьи 1–20; детей ≥ 1 и не больше, чем (семья − 1); подушка > 0, если «есть»;
  срок цели — в будущем; ноль допустим для дохода и расходов.

## 5. Учёт

- **Категории:** у доходных `kind` игнорируется. Добавлен флаг `isDebtPayment` (в ТЗ его нет): без него платежи по
  кредитам нельзя отделить от обязательных расходов. Иконка — эмодзи. Категории не удаляются, только архивируются.
- **Регулярные операции:** только ежемесячные; ожидающие списания **вычисляются** из `nextDueDate`, а не хранятся.
  День 29–31 в коротких месяцах сдвигается на последний день. Обрабатывать нужно по порядку (иначе курсор шаблона
  пришлось бы хранить как набор дат). Одновременно показывается не более 12 просроченных списаний на шаблон.
- **Пагинация:** лимит выборки с догрузкой по 100 записей вместо Paging 3 (ТЗ разрешает оба варианта) — проще,
  без лишней зависимости; агрегаты считаются в SQL и от лимита не зависят.
- **Поиск:** SQLite не умеет регистронезависимый `LIKE` для кириллицы, поэтому у операции есть служебный столбец
  `noteLower`, а категории для поиска подбираются в Kotlin. Спецсимволы `% _ \` экранируются.
- Даты хранятся ISO-строкой (`yyyy-MM-dd`): по ним работают диапазоны и группировка по месяцу.
- Счёт операции — необязательное поле (наличные/карта/накопления), без переводов.
- `memberId` заложен в модель и бэкап, в UI не используется.
- **Лимиты:** на категорию расходов, помесячные; «внимание» с 80%, «превышен» при > 100%.
- **Цели, прогноз:** упрощение — весь плановый свободный поток условно направляется на каждую цель;
  «нужно откладывать в месяц» = остаток / месяцы до срока (округление вверх, минимум 1).

## 6. Резервные копии

- JSON: `{ app, schemaVersion, exportedAt, data: { все таблицы + reminder } }`. Неизвестные поля игнорируются
  (совместимость вперёд), более новая `schemaVersion` отклоняется. Блокировка приложения в бэкап **не** входит.
- Импорт сначала проверяется (структура, ссылки, суммы), потом показывается сводка и выбор «заменить / объединить»
  (по умолчанию — замена с предупреждением).
- Слияние — чистая функция: профиль, опрос и настройки остаются текущими; категории сопоставляются по
  (тип, название без регистра); операции, цели и шаблоны добавляются без точных дублей, лимиты — только отсутствующие.
  Повторный импорт того же файла безопасен.
- CSV: разделитель `;`, десятичная запятая, UTF-8 с BOM (Excel с русской локалью); ячейки, начинающиеся с `= + - @`,
  экранируются апострофом (защита от формульной инъекции).
- На новом устройстве/после переустановки восстановление доступно с приветственного экрана.

## 7. Напоминания

- Цепочка одноразовых задач WorkManager (каждая ставит следующую): точное время без ограничений периодических задач.
  WorkManager сам восстанавливает расписание после перезагрузки; кроме того, расписание пересчитывается при каждом
  запуске приложения (учёт смены часового пояса и перевода часов). Собственного BOOT-приёмника нет.
- Уведомление не показывается, если сегодня уже вносились операции (по времени **внесения**, а не дате операции).
- Разрешение `POST_NOTIFICATIONS` запрашивается при выборе режима напоминаний и при подтверждении привычек в онбординге.
  При отказе приложение работает; в настройках появляется подсказка.
- WorkManager инициализируется вручную (нужна `HiltWorkerFactory`), стандартный инициализатор удалён из манифеста.

## 8. Безопасность и приватность

- В манифесте нет `INTERNET` (и явно удалён `tools:node="remove"` на случай транзитивных библиотек).
- `allowBackup=false` и `data_extraction_rules`, исключающие все данные: облачный бэкап и перенос между устройствами отключены, свой механизм — экспорт в JSON.
- Блокировка: системная биометрия/PIN (`BiometricPrompt`, `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`), собственный PIN не хранится.
  Включается только после успешного подтверждения (нельзя запереть себя), срабатывает при уходе в фон (не при повороте экрана).
- Данные не пишутся в лог.

## 9. UI

- Material 3, светлая/тёмная темы, Dynamic Color на Android 12+, запасные палитры для старых версий.
- Статус показателя всегда = цвет + значок + слово. Красный/зелёный не единственный различитель: график «доходы/расходы»
  использует бирюзовый и янтарный, суммы в списке имеют знак +/−.
- Свайп-удаление операции с отменой; для доступности удаление есть и на экране редактирования.
- Поле суммы форматирует тысячи прямо при вводе (неразрывный пробел), не более двух знаков после запятой.
- Размеры текста — системные (`sp` по умолчанию), касания ≥ 48dp.

## 10. Виджеты рабочего стола

Два виджета (RemoteViews + XML, без Jetpack Glance: нет новой зависимости, раскладки проверяются unit-тестами
Robolectric, поведение одинаково на Android 8–16):

- **2×2 «Добавить операцию»** (`QuickAddWidgetProvider`): только кнопки «Расход» и «Доход». Данных не читает, не
  растягивается (`resizeMode=none`).
- **4×2 «Показатели месяца»** (`MonthWidgetProvider`): слева доходы, расходы и остаток текущего месяца, справа те же
  две кнопки. Растягивается до 5×3 (на Android 12+ `maxResize` 340×200 dp с запасом, на 8–11 предела нет, вёрстка
  просто масштабируется по весам). Нажатие на показатели открывает сводку.

Принятые решения:

- **Только кнопки, без ввода.** RemoteViews не умеет полей ввода, поэтому «Расход» и «Доход» открывают обычную форму
  операции с уже выбранным типом (сумма → категория → «Сохранить»).
- **Что такое «месяц» на виджете.** Календарный, с 1 числа, как во всём приложении: итоги по месяцам считаются в БД
  по `YYYY-MM`, а план из опроса — это «в месяц». Совет по зарплатному периоду — ниже.
- **Суммы целыми, без копеек** (отбрасываются, а не округляются): на виджете мало места.
- **Приватность.** Виджет виден без блокировки, поэтому при включённой блокировке вместо сумм показывается «••••», а
  голосовое описание говорит «суммы скрыты». Для 2×2 это неактуально: сумм у него нет. Отдельной настройки «показывать
  суммы на виджете» нет; если понадобится, её легко добавить (`MonthWidgetState.amountsHidden`).
- **Обновление.** Пока приложение запущено, `WidgetRefresher` перерисовывает виджет при любом изменении операций,
  профиля или блокировки (с задержкой 300 мс, чтобы импорт не вызывал десятки перерисовок). Без процесса: раз в час по
  запросу системы (`updatePeriodMillis`) и при `DATE_CHANGED`/`TIME_SET`/`TIMEZONE_CHANGED`, чтобы месяц сменился в
  полночь. Если лаунчер эти события не доставит, месяц сменится не позже чем через час. Данные читаются одним лёгким
  агрегатом (`StatsRepository.monthCategoryTotals`), без загрузки операций.
- **Передача действия приложению.** Через `Intent.action` (`app.fingramm.action.ADD_EXPENSE` и т.д.), без данных в
  extras. Активность стала `singleTop`: если приложение уже открыто, оно не дублируется, а получает действие в
  `onNewIntent`. Пока приложение заблокировано, действие хранится в `AppViewModel.pendingAction` и выполняется после
  разблокировки. Без профиля (онбординг не пройден) действие игнорируется. После поворота экрана не повторяется.
- **Навигация.** Форма открывается поверх сводки, «Назад» ведёт на сводку. Тип новой операции — необязательный аргумент
  маршрута `type`; прежние вызовы не затронуты.
- **Оформление.** «Расход» красный, «Доход» зелёный, белый текст (контраст ≥ 6:1), плюс знаки − и + и подписи: не
  только цветом. Светлая/тёмная темы через ресурсы цвета (цифры показателей имеют отдельные светлые оттенки для
  тёмной темы). Dynamic Color не используется: RemoteViews не читает тему приложения. У кнопок и блока показателей есть
  `contentDescription` для TalkBack.

**Совет: календарный месяц или период от даты зарплаты.** Сейчас везде календарный месяц; предлагается оставить его
по умолчанию и позже добавить необязательную настройку «День начала месяца» (1–28, по умолчанию 1), а не спрашивать
дату зарплаты. Причины:

- Календарный месяц проще и совпадает со всем остальным: план из опроса, лимиты, графики «по месяцам», регулярные
  операции, сравнение месяцев.
- Дата зарплаты «плавает» (выходные, аванс и зарплата, нерегулярный доход), поэтому «от даты» превращается в догадки;
  число 1–28 не зависит от конкретной выплаты и не ломается в коротких месяцах (поэтому предел 28).
- Техническая стоимость невелика, если делать сразу везде: период операции = месяц от (дата − (N − 1) дней), то есть
  один сдвиг в SQL-агрегате и в расчёте месяца; виджет, сводка, лимиты и графики переключаются вместе. Если же
  завести период только для виджета, цифры на виджете перестанут сходиться со сводкой, и это хуже любого из вариантов.
- Нужно решить две мелочи: как называть период (по месяцу начала или конца: 25 окт → 24 ноя) и что делать с историей
  при смене дня (пересчитывать задним числом: да, ведь период — это представление, а не данные).

Пока это не сделано: решение за вами.

**Не сделано (по желанию):** быстрые кнопки популярных категорий на виджете, настройка «показывать суммы при
блокировке», предпросмотр виджета в списке для Android 8–11 (на 12+ он есть).

## 11. Название и иконка

- **Название.** В интерфейсе, уведомлениях, сообщениях и документации приложение называется **Fingramm**
  (раньше «Семейный бюджет»). Идентификатор пакета (`app.fingramm`) и формат бэкапа (`"app": "fingramm"`) не менялись,
  поэтому ранее сохранённые копии открываются.
- **Иконка.** Нарисована по шаблону заказчика (кошелёк с тремя картами и монетой ₽ на тёмно-синем фоне) как
  адаптивная векторная иконка: фон `#0F1C35`, передний план `ic_launcher_foreground.xml`, монохромный слой
  `ic_launcher_monochrome.xml` для тематических иконок Android 13+. Фигуры и градиенты сняты с картинки (положение и
  наклон карт, монета, строчка, застёжка) и подогнаны сравнением с шаблоном; в безопасную зону 66 dp помещается весь
  кошелёк. Растровые иконки не нужны: минимальная версия Android 8.0. Исходник — `tools/icon/params.json`, генератор
  `tools/icon/make_icon.py` (даёт XML и SVG для просмотра). Нарисована как вектор, поэтому штрихи строчки заданы
  отдельными отрезками (VectorDrawable не поддерживает пунктир), а блики и тени приближены несколькими слоями.

## 12. Что и как проверено

Код писался в среде **без Android SDK и без доступа к Google Maven** (`dl.google.com` закрыт сетевой политикой),
поэтому до отправки в GitHub собрать `:app` не удалось: были проверены `:domain` (104 теста, ktlint, detekt), стиль и
синтаксис `:app` (ktlint, detekt), компиляция `:app` и тестов против Compose Multiplatform с заглушками Android-библиотек,
36 SQL-запросов Room на реальном SQLite и сверка строковых ресурсов.

**Результат CI на PR #1 (Android SDK, JDK 17):** все обязательные задачи зелёные.

- `domain`: `ktlintCheck`, `detekt`, 104 unit-теста.
- `android`: `ktlintCheck`, `detekt`, `test` (unit-тесты `:app`, включая репозитории на Room in-memory через Robolectric),
  `lintRelease`, `assembleRelease`. Тем самым подтверждены Gradle/AGP, KSP (Room, Hilt), манифест, ресурсы и Android Lint
  уровня error, а предположения о реальных API Room/Hilt/WorkManager/DataStore — в части, которую задействуют эти задачи.
- `instrumented` (эмулятор API 34): `OnboardingContentTest` (9 тестов) и `MigrationTest` (2 теста) зелёные;
  схема Room v1 закоммичена в `app/schemas/`.

**Не проверено:**

- Виджеты и иконка на реальном устройстве: внешний вид, растяжение 4×2 → 5×3, нажатия, скрытие сумм при блокировке,
  смена месяца в полночь. Иконка проверена только отрисовкой SVG из тех же фигур и сравнением с шаблоном, а не на
  устройстве.
- Работа на устройстве: уведомления и их восстановление после перезагрузки, блокировка, экспорт/импорт через системный
  выбор файлов, внешний вид, доступность с TalkBack.
